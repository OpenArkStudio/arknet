# 数据库客户端

MySQL 与 Redis 客户端计划用于连接独立的数据库服务端。首版面向单节点部署，
由 arknet 自主实现协议通信，ark 插件负责框架接入。

<Aside type="note" title="开发状态">
MySQL 与 Redis 客户端尚未作为公开 API 发布。开发范围已经确定，连接、连接池与独立服务端
验收需要在发布前完成。协议编解码测试只覆盖其中一部分；通过客户端验收后再提供使用程序与 API 参考。
</Aside>

## 首版范围

| 客户端 | 计划提供的操作 |
| --- | --- |
| MySQL | 查询、参数化预处理、事务 |
| Redis | 通用命令、RESP2／RESP3、流水线请求 |
| 两者共有 | 认证、TLS、连接池、超时、取消、有界队列 |

Redis Cluster、Sentinel 与 Pub/Sub 后续单独开发。支持的服务端版本、认证方式、构建依赖与
API 名称随验收后的实现记录。客户端在 arknet 中自主实现，不采用 Boost.MySQL 或 Boost.Redis。
C++ 实现保持 header-only；现有 TLS 能力使用 OpenSSL。

## 网络库与应用的职责

| 层级 | 职责 |
| --- | --- |
| arknet | 协议拆包与解析、连接 IO、认证、TLS、请求与回复对应、连接池、关闭流程 |
| ark 数据库插件 | 框架配置、模块服务、业务回调接入 |
| 应用 | 查询与命令、事务边界、重试决策、写入结果不确定时的处理 |

客户端先在 arknet 中通过验收，再由 ark 插件直接替换原有数据库驱动，并完成应用回归。

## MySQL 连接与事务

计划中的使用流程为连接与认证、获取池内连接、执行查询或预处理语句，消费完整回复后归还连接。
预处理语句属于创建它的连接。事务从开始到提交或回滚期间使用同一连接租约，
连接池不能把这条连接借给其他操作。

操作中断后，连接需要到达明确的协议边界，或直接丢弃，再处理后续请求。
写操作或提交已经发出、连接随后断开时，结果可能未知。客户端应向调用方保留这个结果，
不能自动重放操作。

## Redis 命令与流水线

计划中的使用流程为连接与认证、接收命令、按顺序消费回复、通知操作完成。
流水线中的命令共用连接，回复必须对应到原命令。RESP3 推送消息不能占用普通命令的完成位置。

尚未发送的排队命令可以取消。命令已经发出后，即使取消或超时，也需要消费对应回复，
或关闭连接后再处理后续命令。写命令没有收到明确回复时，应保留「结果未知」，不能自动重放。

## 发布前验收

| 部分 | 必需证据 |
| --- | --- |
| 编解码 | 分段输入、合并回复、二进制值、畸形长度、嵌套深度、内存上限 |
| 连接 | 独立 MySQL／Redis 服务端互通；认证、TLS 证书与主机名校验、断线、回复顺序 |
| 操作 | MySQL 查询、预处理执行、事务结果；Redis RESP2／RESP3 命令与流水线 |
| 取消 | 发送前取消、在途超时、恰好通知完成一次、下一条回复仍对应正确请求 |
| 连接池 | 获取连接超时、队列拒绝、连接绑定的事务与预处理、排队或在途操作存在时关闭 |
| 并发 | 支持的 IO 模型、共享连接池访问，以及独立的 ASan／UBSan 与 TSan 检查 |
| 持续负载 | 记录运行时长，验证完成次数、队列与连接池内存上限、资源回收 |

互通测试需要记录实际服务端版本与配置。除成功请求外，还需要验证认证与 TLS 失败、
服务端重启、不完整回复、队列饱和及关闭流程。编解码测试结果不能替代连接与连接池验收。

ark 插件接入在客户端验收后单独进行，验证直接替换驱动后的插件调用、配置、业务结果与模块关闭。

## 性能报告

数据库客户端尚未发布性能测量结果。报告发布前，在 `benchmarks/` 中提供可编译的 C++
基准程序；批量测量可以使用 shell 脚本，不增加 Python 或 Ruby 运行要求。

| 维度 | 报告内容 |
| --- | --- |
| 环境 | 客户端与服务端机器、操作系统、数据库版本与配置、编译器、构建模式、依赖版本 |
| 负载 | 操作类型、数据大小、连接数、连接池大小、在途数量、Redis 流水线深度 |
| 执行方式 | 一个 IO context／一个线程、一个 context／多个线程、每线程一个 context；两种 API 都提供后再比较回调与协程 |
| 指标 | 成功操作数／秒、端到端操作时延 p50／p99、客户端与服务端 CPU 占用、内存、队列拒绝数、错误数 |
| 复现 | 仓库中的基准程序与命令、多次独立进程测量、运行时长、支撑最终报告的原始数据 |

分别记录数据库服务端与客户端的开销，并说明使用本机回环还是跨主机网络。
CPU 百分比需说明归一化方式，最终对比使用带单位与测量波动标识的 SVG 图表。
