## 能力组合

```text
发送：应用消息 -> ARQ 数据报 -> 可选 FEC -> UDP
接收：UDP -> FEC 恢复 -> ARQ 排序与重组 -> 应用消息
```

ARQ 提供确认、重传与有序交付，FEC 可以在等待重传之前恢复部分缺失数据报。
例如 10 个数据分片加 2 个校验分片，可恢复组内最多 2 个分片丢失，校验载荷
开销约为 20%，尚未计入头部和填充。较大的分组有利于编码效率，也可能增加
等待时间。未能恢复的丢失继续由 ARQ 处理。

RUDP 保持可靠消息交付约定。允许超时丢弃消息的业务可考虑 UDP + FEC，
但这种组合不能提供 RUDP 的可靠交付约定。

## 候选策略

总体策略与最终提供的预设仍待讨论和测量。

| 候选 | 行为 | 适用要求 |
| --- | --- | --- |
| 仅 ARQ | 不发送校验分片 | 需要可靠交付，网络丢失较少，控制额外带宽 |
| ARQ + 自适应 FEC | 按预设阈值与预算调整校验分片 | 需要可靠交付，恢复延迟预算较紧 |
| ARQ + 固定 FEC | 使用固定编码参数 | 链路特征已测量，冗余开销需要可预测 |

应用提前配置动态启用条件。运行时调整必须遵守这些限制，并能查询当前参数及
每次调整的原因。具体数值阈值尚未确定。

## 参数要求

| 参数类别 | 计划提供的控制 |
| --- | --- |
| 启用条件 | 最小样本数、统计窗口、丢失／重传阈值、恢复延迟目标 |
| 编码预算 | 数据／校验分片上限、额外字节预算、最小有效分组大小 |
| 延迟预算 | 最长组包等待、乱序宽限时间、分组解码截止时间 |
| 稳定性 | 不同的启用／退出阈值、冷却时间、降低冗余前的连续稳定窗口 |
| 过载处理 | 发送队列限额、RTT／队列增长保护、可选的应用负载上限 |
| 可观测性 | 原始数据报、校验字节、恢复／缺失分片、ARQ 重传、当前参数与切换原因 |

丢失统计需要区分乱序与缺失，以及 FEC 恢复与后续 ARQ 重传。样本不足时保持
当前策略。分组较小或发送稀疏时，也要遵守延迟与字节预算；预算内无法形成有效
编码分组时，由 ARQ 直接发送，不增加校验分片。

增加冗余不能解决过载。RTT 与队列持续增长时，需要保守地控制发送速率；这两个
指标都不能单独证明丢包原因。ARQ 拥塞控制继续生效，CPU 与带宽预算应防止
自适应冗余加重发送端或接收端的负载。

## 报文格式与限制

连接建立时，两端先确定支持 FEC 的报文模式。该模式内，校验分片数量为零表示
冗余未启用，不表示连接切换回裸 KCP 报文。每组携带实际编码参数，发送端可以
调整后续分组，接收端仍能分别解码。

报文需要版本、conversation／分组／分片标识、长度，以及分配内存前的严格校验。
FEC 头部与填充必须计入 UDP MTU 和内存预算。分组数量、保留字节与解码寿命
均需有界，控制报文不能等待数据分组填满。兼容 KCP 的 ARQ-only 模式仍可独立使用。

## 确定默认值前的验证

在随机丢失、突发丢失、乱序、不同 RTT、稀疏／持续流量及接收队列溢出场景下，
对比 ARQ、固定 FEC 与自适应 FEC。测量交付正确性、p50／p99 RTT、额外发送
字节、CPU 占用与内存，同时覆盖对端兼容、无效分组、参数切换与未完成分组的停止。

编码引擎、预设名称与数值、调整算法及协商格式尚未选定，将在当前 RUDP 验证与
后续有损网络实验完成后确定。
